FTEシミュレーション
ロジック解説

MR（医薬情報担当者）のリソースアロケーションを定量的に算出する シミュレーションシステムの計算ロジックを、各ステップごとに詳細に解説します。

対象期間 FY2026〜FY2035（10年間）
対象品目数 18品目（CS 15品目 / PS 3品目）
現行MR数 CS 380名 / PS 45名
計算粒度 品目 × 月別
★

ひとめでわかる最適FTE推定ロジック

MR人員（FTE）の最適配分は、以下の問いに答えるシステムです。
「CS 380名・PS 45名というヘッドカウント制約の中で、どの品目に何人のMRを月ごとに割り当てれば売上が最大になるか？」
目的と主な入力データ
目的
  • 品目×月別の最適 MR 投入量（FTE）を算出
  • ヘッドカウント制約内で売上最大化の配分を決定
  • 新発売品の立ち上げ投資と既存品目の最適縮小を両立
主な入力データ
  • 活動実績（〜2026/3/31）: 医師ID・施設・訪問頻度
  • 品目マスタ: 発売日・LOE・患者数・適応数
  • MMM出力: Hill応答曲線パラメータ・Adstock減衰率
  • FC/SC設定: 品目ペア・担当比率
計算の流れ ― 7ステップ
1
ターゲット医師数の算出
活動実績（〜2026/3）から施設カバレッジを推定し、品目ごとの訪問対象医師数を決定する。 新発売品は参照品（類似品目）の医師数を基準に推計。
2
FC / SC 分割
MR は複数品目を同一訪問で担当する（セカンドコール）。 品目間の医師被り率を計算し、主担当（FC）と同行担当（SC）に分割。 SCのFTEコストはFCの10%のみ計上（同一訪問内で追加時間が少ないため）。
3
訪問頻度の推定（ライフサイクル補正）
実績ベースの月次訪問頻度に、ライフサイクル段階に応じた補正を乗算。 発売後12ヶ月以内: ×1.3 LOE前12ヶ月: ×0.7 LOE後: ×0.3
4
MR / デジタル比率の推定
MMMの出力するAdstock減衰パラメータから各チャネルの限界応答を計算し、 MR活動とデジタル活動の最適比率を品目ごとに推定。 減衰が遅い（効果が長続きする）チャネルほど、デジタル比率が高くなる傾向。
5
FTE 算出（コア計算）
FTE = ターゲット医師数 × 訪問頻度[回/月] × MR比率 ÷（稼働日[20日] × コール/日[CS:2.5 / PS:1.5]）
FCとSCのFTEを別々に算出し、合算して品目×月別の必要FTEを得る。
6
新発売品への FTE 移動
OVE・Zaso・WSA の発売時に必要なFTEを、既存品目から削出する。 削出量は MMMの Hill 関数から算出した限界ROIの逆数に比例して配分 （ROIが低い品目ほど多く削る）。ランチカーブで発売後の月次投資量を制御。
7
正規化・ROI最大化最適配分
① ヘッドカウント正規化: 毎月の領域合計がCS 380名・PS 45名になるよう品目間比率を保ちながらスケーリング。
② ROI最大化配分: MMMのHill応答曲線の一次微分（限界収益）が全品目で均等になる点が最適配分。 この「等限界収益の原則」により、追加の1 FTEが最も多くの売上を生む品目に自動的に集中する。
💡 活動実績データの期間: 訪問頻度・FC/SC被り率の推定に使用する活動データは 〜2026年3月31日 の実績値を使用。 納入実績データも同期間。FY2026以降の予測値は sales_forecast.csv で管理し、ROI最適配分の基準とする。

1

ターゲット医師数の算出

各品目・各月において、MRが訪問すべき医師の数を算出します。 既存品は過去の実績から、新発売品は類似品の規模を参照しながら発売後の浸透率カーブに基づいて推定します。
既存品目の場合

直近12ヶ月の月別ユニーク医師数の平均を基本値として使用します。

// 直近12ヶ月の月別ユニーク医師数 → 平均
base_target = mean( monthly_unique_doctors[-12:] )

※ target_doctors.csv でキャッシュとして保持し、過去実績が不足する場合に使用

新発売品の場合

類似品（参照品）のターゲット医師数をベースに、患者規模・効能数・浸透率カーブで補正します。

// 参照品ベース × 患者数比 × √効能数比 × ランプアップ
target = base_ref
  × (patients_new / patients_ref)
  × √(indications_new / indications_ref)
  × ramp_up_curve[months_since_launch]
ランチカーブ（新発売品浸透率）の考え方

新発売品は発売直後に最大限の活動を投下し（1.00）、普及が進むにつれてメンテナンスモードに移行します。 各品目の特性に合わせて任意の形状を設定できます。

2

ファーストコール / セカンドコール 分割

ターゲット医師を「主訪問（FC：ファーストコール）」と「付随訪問（SC：セカンドコール）」に分割します。 SCはFC訪問に内包されるため、FTEコストはFCの10分の1として計上します。
方式①：FC比率の明示指定（推奨）

fc_sc_ratio.csv に品目ごとのFC比率を設定します。 実績や戦略的判断に基づいて直接指定できる最もシンプルな方式です。

// FC比率をCSVから直接読み込んで適用
fc_doctors = round(total × fc_ratio)
sc_doctors = total - fc_doctors
デフォルトで優先適用
方式②：被り率ベース（フォールバック）

FC品目とSC品目のターゲット医師リストの重複割合（被り率）から、 SCとして訪問する医師数を自動計算します。

// 医師IDリストの積集合から被り率を算出
overlap_rate = |FC ∩ SC| / |SC|
sc_doctors = Σ(overlap_rate × total)
fc_doctors = total - sc_doctors
fc_ratioが未設定の場合に適用
FC/SC によるFTEコスト計算

SC訪問はFC訪問と同じ医師への同一訪問機会に内包されるため、追加コストはFC の 10%のみ計上します。

// SC_COEFFICIENT = 0.1（セカンドコールのFTE換算係数）
required_calls = fc_doctors × freq + sc_doctors × freq × 0.1
💡
SC訪問のコスト係数 0.1 は「FCと同じ訪問機会の中でSCを実施するため、追加工数はほぼゼロだが無視もできない」という実態を反映した値です。この係数は設計上の判断として固定されています。
3

訪問頻度の推定

医師1人あたり・月あたりの訪問頻度を推定します。 実績データをベースに、品目のライフサイクルフェーズ・競合状況・効能追加などの外部要因で補正します。

モードロジック用途
actual 過去活動データの医師×月別コール数の平均値をそのまま使用 過去実績の再現・検証
lifecycle_adjusted 実績平均にライフサイクル補正係数を乗じて将来を推定 デフォルト（将来予測に推奨）

競合参入ブースト

競合品の発売に合わせて、防衛的な活動強化を一時的に上乗せします。

// 競合発売後の経過月数に応じて線形減衰
boost = 1 + (intensity - 1)
      × (1 - elapsed / boost_months)
🔢 パラメータ例（competitor_schedule.csv）
intensity = 1.25 → 最大 +25% のFTE増
boost_months = 18 → 18ヶ月かけて線形減衰
複数競合が重なる場合は最大値を採用
効能追加ブースト

新しい効能が追加承認された時点から、一時的な訪問頻度の増強を加算します。

// 効能追加後の経過月数に応じて線形減衰
boost = 1 + (ind_boost - 1)
      × (1 - elapsed / ind_boost_months)
🔢 パラメータ例（products.csv）
indication_fte_boost = 1.30 → 最大 +30%
indication_boost_months = 6 → 6ヶ月で収束
indication_add_ym に効能追加月を設定
4

MR / デジタル活動比率の推定

品目ごとに、MRが訪問で実施する活動とデジタルチャネルが代替する活動の比率を、 MMMのHill関数（限界収益）とFTE規模の2つの観点から算出します。
Hill関数による限界収益スコア

Meridian（MMM）が推定するHill関数の微分値（＝追加1活動あたりの限界収益）を MRとデジタルそれぞれで計算し、その比率をチャネル配分の基準とします。

// Hill関数（売上応答曲線）
R(a) = β × aslope / (ecslope + aslope)

// 限界収益（Hill関数の一次導関数）
dR/da = β × slope × ecslope × a(slope-1)
       ÷ (ecslope + aslope)2

// チャネル比率（MR vs Digital）
mr_score = dR/da|MR × β_MR × ec_MR
mr_ratio = mr_score / (mr_score + digital_score)
パラメータ意味値の傾向と影響
β（beta）応答曲線のスケール係数大きいほど当該チャネルの限界収益が高く、比率が上がる
ec（EC50）半最大効果到達活動量小さいほど少ない活動で飽和 → 既に十分な場合は追加効果小
slopeHill係数（曲線の傾き）>1でS字（急激な飽和）、=1で双曲線、<1で緩やかな飽和
alphaAdstock減衰率効果の持越し期間。比率算出では使用しない（MMMの別パラメータ）
FTE規模によるMR比率の微調整（Pass 2）

Hill関数スコアで算出した比率に加え、品目の相対的なFTE規模でMR比率を補正します。 FTEが多い（重点品目）ほどMR比率を高く、少ない（サポート品目）ほど低く設定します。

// エリア×月の全品目base_fteの平均を基準に相対化
area_avg = mean(base_fte) by (area, month)
relative = base_fte / area_avg

// 線形補正（mr_ratio_params.csv でチューニング可）
mr_ratio = clip(0.65 + 0.20 × (relative - 1),
          0.40, 0.90)
🔵 FTEが大きい品目（relative > 1）
MR比率 UP（最大 90%）
重点品目として人的活動を厚く配分
🟡 FTEが小さい品目（relative < 1）
MR比率 DOWN（最小 40%）
デジタルチャネルへのシフトを促進
5

FTEの算出（コア計算）

ターゲット医師数・FC/SC分割・訪問頻度・MR比率を統合し、MR headcount（FTE）を算出します。 これが全計算の中核となるステップです。
FTE計算の全数式
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ Step A: 必要コール数（月間） ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
required_calls
  = fc_doctors × visit_freq
  + sc_doctors × visit_freq × 0.1

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ Step B: base_fte（全チャネル合算の必要人員） ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
base_fte
  = required_calls
  ÷ (CALLS_PER_DAY[area] × 20日)
  × indication_boost × competition_boost

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━ Step C: required_fte（MR headcount） ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
required_fte = base_fte × mr_ratio
digital_fte = base_fte × digital_ratio ← 参考値
A
必要コール数の計算
FC医師への訪問数とSC医師への付随訪問（係数0.1）を合算して月間コール数を求めます。訪問頻度は Step 3 で推定した値を使用します。
B
月間キャパシティで除してbase_FTEを計算
CS領域：50コール/月（=2.5コール/日 × 20日）、PS領域：30コール/月で除算します。さらに効能追加ブーストと競合ブーストを乗じます。
C
MR比率を掛けてrequired_FTEを確定
Step 4 で算出したMR比率を乗算して、MR headcount（FTE）を求めます。デジタルFTE（参考値）は 1 - mr_ratio で計算します。
⚠️
2パス方式による計算順序：MR比率の計算には「エリア×月別のbase_fte平均」が必要なため、全品目のbase_fteを計算してから（Pass 1）、MR比率を決定して最終FTEを算出する（Pass 2）という2段階で処理しています。
6

新発売品へのFTE移動

MR総数は固定（CS=380名）のため、新発売品のFTEは既存品目から拠出する必要があります。 限界ROI（収益効率）の低い品目から優先的に削減し、リソースの最適な再配分を実現します。
動的FTE移動のアルゴリズム

新品目の成長（ランチカーブ）に比例して、ドナー品目から月別に段階的に削減します。 一括削減ではなく、新品目の実際の成長速度に合わせた自然な移行を表現します。

1
新品目のピーク時FTEを算出
ランチカーブが最大（発売月）の時点のFTEをピーク値として決定します。このピーク値が「ドナー品目から移動が必要な最大量」になります。
2
月別削減量の決定（ランチカーブに比例）
各月のドナー削減量 ＝ ピーク削減量 × （当月新品目FTE ÷ ピーク時FTE）
reduction(t) = peak_reduction × (new_fte(t) / peak_fte)
3
ドナー品目への按分（限界ROI逆数按分）
削減量をドナー品目に配分する際は、限界ROIが低い（投資効率が低い）品目から優先して削減します。現FTEの50%を下限として保護します。
限界ROI逆数按分の計算式
// 各ドナー品目の限界ROI（= dR/da at 現在の活動量）
marginal_roi[p] = dR/da(current_mr_activity[p])

// ROIが低いほど多く削減（逆数で重みづけ）
weight[p] = (1 / marginal_roi[p]) / Σ(1 / marginal_roi)
reduction[p] = total_reduction × weight[p]

// 下限制約（現FTEの50%以上を維持）
new_fte[p] = max(current_fte[p] - reduction[p],
            current_fte[p] × 0.5)
💡
min_fte_ratio = 0.5 の設定により、いかなる状況でも既存品目の現行FTEが半分以下に削られることはありません。製品サポートの最低水準を保護するための制約です。
7

正規化・離散化

算出したFTEを実際のMR人数計画として使える形に変換します。 まず月別エリア合計を現行MR数にスケーリングし（正規化）、 次に半期単位のステップ関数に変換（離散化）することで、 現実的で実行可能な計画値を生成します。
①正規化：ヘッドカウント制約への適合

月別のエリア合計FTEが現行MR数（CS=380, PS=45）と一致するよう、 品目間の相対比を保ったままスケーリングします。

// エリア × 月ごとにスケール係数を計算
scale = target_headcount / Σ(required_fte)
adjusted_fte = required_fte × scale
✓ CS全品目の月間FTE合計 → 常に380名
✓ PS全品目の月間FTE合計 → 常に45名
✓ 品目間の比率は保持される
②離散化：半期ステップ関数への変換

連続的な月次FTEを半期（H1: 4〜9月、H2: 10〜3月）の平均値に統一します。 人員計画の安定性を確保し、頻繁な配置換えを防ぎます。

// 半期内の月次FTE平均 → 全月に適用
half_avg = mean(fte) by (product, half)
fte[half] = half_avg // 期内全月に同一値
// 再度ヘッドカウント正規化を適用
→ normalize_fte_to_headcount()
✓ 半期内のFTEは一定値（ステップ関数）
✓ 半期ごとに切り替えポイントあり
✓ 離散化後に再度正規化を適用

ROI最大化 最適FTE配分

シミュレーションFTEとは独立して、売上最大化を目的とした理論的な最適配分を算出します。 MMMのHill関数に基づく「等限界収益条件」を使い、全品目の限界収益が均等になるFTE配分を数値的に求めます。 この値とシミュレーションFTEの差がリソース再配分の余地を示します。
等限界収益原理（経済学的背景）

限られたリソース（MR人員）を複数品目に配分する際、 各品目の追加1単位あたりの収益増加（限界収益）が等しくなる点で 全体の売上が最大化されます。

⚖️ 直感的な説明
品目Aの限界収益 > 品目Bの限界収益 → Bの人員をAに移す
品目Aの限界収益 < 品目Bの限界収益 → Aの人員をBに移す
品目AとBの限界収益が等しい → 最適（これ以上の改善なし）
// 最適条件（等限界収益）
dR_A/da_A = dR_B/da_B = ... = λ*

// ヘッドカウント制約
Σ(a_p / capacity) = budget

// λ*（均衡限界収益）を探索
lam_star = binary_search(λ)
a_opt[p] = solve(dR/da = lam_star)
2段階バイナリサーチアルゴリズム

均衡限界収益 λ* と各品目の最適活動量を、2層の数値探索で効率的に求めます。

外
外側ループ：λ（均衡限界収益）のバイナリサーチ
λを仮定 → 全品目の最適活動量を計算 → 合計FTEとbudgetの差を確認 → λを調整。 log-scaleで200回反復し収束させます。
// total_fte(λ) > budget → λを上げる（活動量を絞る）
// total_fte(λ) < budget → λを下げる（活動量を増やす）
内
内側ループ：品目ごとの最適活動量を探索
固定されたλに対し、dR/da = λ を満たす活動量を品目ごとにバイナリサーチ（100回反復）で求めます。 Hill係数が1以上のS字曲線の場合は変曲点を起点として収穫逓減域のみ探索します。
変
活動量 → FTE変換と正規化
最適活動量を月間キャパシティで除してFTEに変換し、budgetに対する誤差補正のため最終スケーリングを行います。
optimal_fte[p] = a_opt[p] / capacity
scale = budget / Σ(optimal_fte)
optimal_fte[p] *= scale
📅
各FYの代表月として9月（Q2中月）を使用し、季節変動の影響を最小化しています。LOE後・未発売品目の最適FTEは0として扱います。
